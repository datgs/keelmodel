# Proposed Repository Structure

```text
keelmodel/
├── pyproject.toml
├── README.md
├── src/
│   ├── keelmodel/
│   │   ├── __init__.py
│   │   ├── schema/             # YAML loading, validation, model definitions
│   │   ├── generation/         # deterministic Python model generation
│   │   ├── registry.py         # explicit module/model registration
│   │   ├── runtime/            # sync data API, queries, transactions, errors
│   │   ├── extensions/
│   │   │   ├── field_auth/     # optional field read/create/update/filter/order checks
│   │   │   └── audit/          # optional same-transaction audit
│   │   └── migrations/         # Alembic integration and draft generation
│   └── keelpolicy/
│       ├── __init__.py
│       ├── schema.py           # policy YAML parsing/validation
│       └── evaluate.py        # policy evaluation, no ORM/database dependency
├── tests/
│   ├── unit/
│   ├── integration/
│   └── fixtures/
├── examples/
│   └── sales/                  # sample application-owned module
│       ├── keelmodule.yaml
│       ├── models/
│       │   └── invoice.yaml
│       ├── policies/
│       │   └── authorization.yaml
│       └── generated/          # generated by KeelModel; not hand-edited
└── docs/
```

## Ownership rules

- `src/keelmodel/` contains the data SDK; `src/keelpolicy/` contains the policy library. They are separate Python packages in this same repository.
- Model YAML and policy YAML are separate application/module-owned sources.
- Generated model Python lives under the owning application/module, not inside the SDK package.
- `keelpolicy` stays in this repository for v1 and has no dependency on KeelModel, SQLAlchemy, or PostgreSQL. KeelModel may depend on `keelpolicy`; the reverse dependency is forbidden.
- KeelModel runtime translates policy record conditions into database predicates and calls an explicitly enabled field authorization extension.
- Extensions do not use generic hooks and do not load automatically.
- Directory boundaries are guidance; do not split a cohesive implementation into extra files solely to match this tree.
